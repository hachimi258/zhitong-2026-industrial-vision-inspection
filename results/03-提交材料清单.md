## 八、图片优化说明（`答辩.pptx` 与关键效果图）

入库的图片类材料做过两类**像素尺寸不变、仅重新编码**的优化，目的是控制仓库体积。原始文件均保留在项目目录中。

### 8.1 `答辩.pptx`：57.9 MB → 38.9 MB

**原因**：原始 `.pptx` 为 57.9 MB，**超过 GitHub Contents API 的单次上传上限（约 50 MB）**，无法直接入库。

**做法**：仅对 `ppt/media/` 下的 PNG 图片**原地重新编码**（保持**原文件名与像素尺寸**不变，
因此 `rels`、`[Content_Types].xml`、幻灯片引用**全部保持有效**）。
对带透明通道的图片先合成到白底再编码。

**结果**：

| 项 | 原文件 | 优化后 |
|:---|:---|:---|
| 大小 | 57.9 MB（60,669,061 B） | **38.9 MB** |
| ZIP 条目数 | 355 | **355**（一致） |
| 条目名集合 | — | **与原文件完全一致** |
| 幻灯片数 | 14 | **14**（已用 PowerPoint 实际打开验证） |
| 最大单图 | `image3.png` 11.72 MB → 0.81 MB | `image51.png` 8.25 MB → 1.50 MB |

**原件指纹**（如需未压缩版本，可用 SHA256 校验手头副本）：

| 项 | 值 |
|:---|:---|
| 大小 | 60,669,061 B（57.9 MB） |
| SHA256 | `B1EA5828572A3C75CF4664AF1BA172574349E3A9DAAE85BAF0725A4A0BB2454A` |
| 位置 | 原项目目录；另在 `26计应-工视\答辩_original_57.9MB.pptx` 留有一份副本 |

### 8.2 关键效果图：三张 BMP → JPEG
