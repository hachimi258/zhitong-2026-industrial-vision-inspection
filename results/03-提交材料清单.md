### 想把这些大文件也放到 GitHub 上？

GitHub 仓库单文件上限 **100 MB**，另外**超过 50 MB 会给出警告**。三种可行办法：

**① GitHub Release（最简单，单文件上限 2 GB）**

```bash
# 需要已安装 gh CLI 并登录
gh release create v1.0 "26VM本科组方案.sol" "26-4C-VM演示.mp4" \
  --title "智瞳工检 v1.0 成果附件" \
  --notes "VisionMaster 方案文件与作品演示视频（超过仓库单文件上限，故以 Release 附件分发）"
```

**② Git LFS（在仓库内以指针托管）**

```bash
git lfs install
git lfs track "*.sol" "*.mp4"
git add .gitattributes
git add "26VM本科组方案.sol" "26-4C-VM演示.mp4"
git commit -m "assets: 添加 VisionMaster 方案与演示视频（Git LFS）"
git push
```

**③ 外链分发（网盘）**

按竞赛提交方式上传到网盘，把**下载地址与 SHA256** 写进本文件即可。
（原文作品信息概要表中这六项均标注为「已上传到网盘」。）

## 七、图片优化说明（`答辩.pptx` 与关键效果图）

入库的图片类材料做过两类**像素尺寸不变、仅重新编码**的优化，目的是控制仓库体积。原始文件均保留在项目目录中。

### 7.1 `答辩.pptx`：57.9 MB → 38.9 MB

**原因**：原始 `.pptx` 为 57.9 MB，**超过 GitHub Contents API 的单次上传上限（约 50 MB）**，无法直接入库。

**做法**：仅对 `ppt/media/` 下的 PNG 图片**原地重新编码**（保持**原文件名与像素尺寸**不变，
因此 `rels`、`[Content_Types].xml`、幻灯片引用**全部保持有效**）。
对带透明通道的图片先合成到白底再编码。

**结果**：

| 项 | 原文件 | 优化后 |
|:---|:---|:---|
| 大小 | 57.9 MB（60,669,061 B） | **38.9 MB** |
| ZIP 条目数 | 355 | **355**（一致） |
| 条目名集合 | — | **与原文件完全一致** |
| 幻灯片数 | 14 | **14**（已用 PowerPoint 实际打开验证） |
| 最大单图 | `image3.png` 11.72 MB → 0.81 MB | `image51.png` 8.25 MB → 1.50 MB |

**原件指纹**（如需未压缩版本，可用 SHA256 校验手头副本）：

| 项 | 值 |
|:---|:---|
| 大小 | 60,669,061 B（57.9 MB） |
| SHA256 | `B1EA5828572A3C75CF4664AF1BA172574349E3A9DAAE85BAF0725A4A0BB2454A` |
| 位置 | 原项目目录；另在 `26计应-工视\答辩_original_57.9MB.pptx` 留有一份副本 |

### 7.2 关键效果图：三张 BMP → JPEG

`results/关键图片/` 中有三张原为 **BMP** 格式（每张 **35.0 MB**）：

| 原文件 | 尺寸 | 原大小 | 转换后 |
|:---|:---|:---|:---|
| `编码_2.jpg_1.bmp` | 4024×3036 | 35.0 MB | `编码_2.jpg_1.jpg`（1.29 MB） |
| `编码_3.jpg_2.bmp` | 4024×3036 | 35.0 MB | `编码_3.jpg_2.jpg`（1.30 MB） |
| `芬达_2.jpg_1.bmp` | 4024×3036 | 35.0 MB | `芬达_2.jpg_1.jpg`（1.29 MB） |

> **像素尺寸完全保留**（4024×3036 不变），仅为 JPEG（quality 92）无损视觉转换。
> 之所以特别说明：这三张的分辨率与原文测试环境配置表记录的图像分辨率**完全一致**，
