## 一、总体技术路线

系统以 VisionMaster 平台为核心，采用**本地图像源**作为输入，采用：

```
图像输入 — 图像预处理 — 任务分流 — 模型/算法检测 — 结果判定 — 图像渲染与保存
```

**模块化设计**是核心思想：五类任务**分别搭建独立视觉流程**，但在
**图像输入、结果判定、结果渲染、耗时统计、本地保存**五个环节保持统一。
原文理由是"若所有任务混合在同一流程中处理，容易造成流程复杂、参数相互影响、调试困难"。

### 系统分层（原文设计说明书 3.1.1）

| 层级 | 职责 |
|:---|:---|
| 图像输入层 | 加载本地测试图像 |
| 算法处理层 | 分类模型、高精度模板匹配、二值化、形态学处理、圆查找、分割模型、OCR 识别 |
| 结果判定层 | 输出类别、数量、OK/NG、缺陷区域、编码内容 |
| 界面展示层 | 显示检测图像、历史结果、运行耗时并保存结果图片 |

**架构选择理由**（原文）：属典型工业现场检测应用，对实时性与稳定性要求高；
集中式处理可减少数据传输延迟；VisionMaster 提供丰富算法工具并支持模块化流程搭建。

## 二、五类任务的技术方案

### 2.1 饮料分类检测 —— 深度学习图像分类

**问题**：同一饮料在不同角度下外观差异大；不同饮料间也可能颜色接近；受光照与反光影响。

**方案**：
- 训练阶段按饮料类别对样本**分类标注**（整图类别标签）
- 数据增强：**旋转、亮度变化、对比度变化**，提升对拍摄角度与光照的适应性
- 模型选择：原文明确**"并不单纯选择参数量最大的模型，而是在分类准确率和推理速度之间进行平衡"**
- 推理阶段：图像输入 DL 分类模型 → 输出类别名称及置信度 → 取最高置信度类别 → 图形收集模块叠加显示

**调试要点**：重点观察分类置信度与错误样本，对易混淆类别**补充样本并重新训练**。

> 实施细节：数据增强由自写脚本 [../code/增强.py](../code/增强.py) 完成 —— 见 §四。

### 2.2 木棍目标计数 —— 高精度模板匹配

**问题**：木棍外观相似、数量较多、排列密集，易粘连；背景阴影噪点可能被误识别。

**方案**：
1. 从样本图像中选取代表性木棍**局部特征建立模板**
2. 在整图或指定 ROI 内搜索相似目标，输出匹配框、中心点、角度、尺度、匹配分数
3. 按有效匹配结果数量得到计数
4. 图形收集模块叠加匹配位置与计数结果

**四个核心调节参数及其权衡**（原文 4.4）：

| 参数 | 调低的后果 | 调高的后果 |
|:---|:---|:---|
| 最小匹配分数 | 容易误检 | 可能漏检部分目标 |
| 最大匹配个数 | — | 需结合样本中木棍数量范围设置 |
| 角度范围 | — | 用于适应木棍摆放方向变化 |
| 尺度范围 | — | 用于适应目标大小的轻微变化 |

### 2.3 纸杯尺寸检测 —— Sauvola 二值化 + 形态学 + 圆查找

**问题**：单个纸杯与叠放纸杯的图像差异**很小** —— 叠放后杯口到相机距离变化，
图像中杯口圆形半径出现细微变化。

**方案（四步）**：

| 步骤 | 方法 | 关键参数 |
|:---|:---|:---|
| ① 二值化 | **Sauvola 局部自适应二值化**分离杯口边缘 | 校正系数、动态范围、滤波核宽度、滤波核高度 |
| ② 形态学去噪 | **开运算**（先腐蚀后膨胀）去小面积孤立噪点，保持圆形边缘 | — |
| ③ 圆查找 | 多**卡尺**方向搜索圆周边缘点 → 拟合圆 → 输出圆心、半径、拟合误差 | 扇环半径范围、边缘类型、边缘极性、边缘阈值、滤波尺寸、卡尺数量 |
| ④ 条件判定 | 半径与阈值比较 | **阈值 1055 像素** |

**判定逻辑**：
- 检测半径 **> 阈值** → 判定**叠放**，输出 **NG**
- 检测半径 **≤ 阈值** → 判定**单个**，输出 **OK**

**为什么用 Sauvola 而非固定阈值**（原文）：纸杯图像存在光照不均、背景噪声、边缘灰度变化，
固定阈值二值化容易出现边缘断裂或背景噪点过多。

**卡尺数量的权衡**（原文）：卡尺数量越多，圆拟合越稳定，但**检测耗时也增加**，
需在检测精度与运行速度间平衡。

> 这是全套方案中最"几何化"的一环，也是耗时最低的模块（约 62.98 ms）。

### 2.4 纸杯缺陷检测 —— 深度学习图像分割

**问题**：缺陷类型多（杯壁污损、杯底污损、杯口损坏、杯体变形、破损或撕裂）、
形态不规则、位置不固定；纸杯表面阴影与反光易与缺陷混淆。

**方案**：
- 训练阶段对缺陷样本做**像素级/区域级标注**，按缺陷类型设不同标签
  （杯壁污损、杯底污损、杯口破损、变形等）
- 推理阶段模型输出缺陷概率图/类别图 → 按**最小分数阈值**过滤低置信度区域 →
  区域分析提取缺陷轮廓、位置、面积
- 判定：无有效缺陷区域 → **OK**；检测到缺陷区域 → **NG**
- 图形收集模块标注缺陷位置并输出缺陷类别

**为什么用分割而非分类**（原文）：分割模型不仅判断"是否有缺陷"，
还能**输出缺陷所在区域**，更适合工业质检对缺陷位置标注的需求。

### 2.5 饮料编码 OCR 识别 —— 两阶段（定位 + 识别）

**问题**：字符小、对比度低、背景干扰强、方向不固定；点阵印刷易断裂、边缘模糊；
罐底/瓶身存在反光与曲面变形。**直接对整图做 OCR 会让背景干扰字符定位**。

**方案（三阶段）**：

| 阶段 | 方法 | 要点 |
|:---|:---|:---|
| ① 图像预处理 | **Sauvola 二值化** → **中值滤波**去孤立噪点 → **形态学处理**增强点阵字符连接性 | 调校正系数、动态范围、滤波核尺寸 |
| ② 字符定位 | **DL 字符定位模型**；训练时用**带角度矩形框**标注，使模型输出含角度信息的定位框，适应 **360° 方向变化** | 最大查找个数、最小置信度、最小平均分数、最大重叠率；目标排序按置信度 |
| ③ 字符识别 | 将定位框作为 **ROI** 输入 **DL 字符识别模型**，识别具体编码内容 | 定位与识别模型分开设计以**减少背景干扰** |

**形态学处理为何对点阵字符尤其重要**（原文）：点阵字符本身由多个离散点组成，
若不适当连接，会影响字符定位与识别。

**输出**：识别结果以文字叠加显示，并保存带 OCR 结果的图片。

### 2.6 结果渲染与本地保存 —— 统一末端

五个流程末端**统一设置**：图形收集 + 耗时统计 + 输出图像模块。

**渲染内容**：分类标签、目标检测框、目标数量、纸杯圆形轮廓、半径数值、
OK/NG 判定、缺陷区域、OCR 编码文本、检测耗时。

**保存规范**（原文 3.2.1 存储数据）：

```
任务类型_序号_时间.jpg
示例：defect_01_20260414.jpg
```

- `任务类型` 表示检测类别（如 `defect`、`size`、`ocr` 等）
- `序号` 表示当前检测编号
- `时间` 表示检测时间
- 按**检测任务类型分类存放**在不同文件夹

> 原文说明：系统**未使用数据库**，检测结果以图像文件及日志形式保存至本地。

## 三、数据与训练平台

### 3.1 数据管理

- 数据来源：**竞赛提供的数据集** + 团队整理的本地测试样本
- 按任务类型分类存放（饮料分类、木棍计数、纸杯尺寸、纸杯缺陷、饮料编码 OCR），
  再按类别/缺陷类型/检测任务细分文件夹

### 3.2 训练平台设计（原文 3.2）

为提高模型训练与管理的规范性，项目在开发工具体系中**加入训练平台设计**：

```
数据导入 → 样本标注 → 数据增强 → 模型训练 → 模型验证 → 模型管理 → 部署到检测流程
```

**三类任务的标注方式**（原文 4.2.1）：

| 任务 | 标注方式 |
|:---|:---|
| 饮料分类 | 按类别标注**整张图像** |
| 纸杯缺陷 | 按**缺陷区域**做分割标注（如杯底污损区域框选并标注对应缺陷类别） |
| OCR 识别 | 使用**带角度的矩形框**标注字符区域，并输入**文本真值** |

**引入训练平台的理由**（原文）：避免样本混乱、标注不统一、模型版本难以管理。

## 四、自写代码：数据增强脚本

全项目**唯一的自写代码**是根目录的 `增强.py`（7.7 KB），用于扩充分类训练样本。

- **输入/输出**：`e:/desktop/demo/1` → `e:/desktop/demo/2`（递归处理子文件夹，保留目录结构）
- **每张原图生成**：5 张增强图（命名 `<原名>_aug<N>.<ext>`）

**增强项与参数**（脚本 `PARAMS` 字典，全部可调）：

| 类别 | 参数 | 值 |
|:---|:---|:---|
| 几何 | 随机旋转 | ±15° |
| 几何 | 随机裁剪缩放 | 0.9 ~ 1.1 |
| 几何 | 水平/垂直翻转 | False / False |
| 色彩 | 亮度变化 | ±0.2 |
| 色彩 | 对比度变化 | ±0.1 |
| 色彩 | 饱和度变化 | ±0.1 |
| 色彩 | 色调偏移 | ±0.1 |
| 其他 | 高斯噪声标准差 | 5 |
| 其他 | 高斯模糊核大小 | 3 |

**实现要点**：
- 色彩增强在 **HSV 空间**完成（V 通道调亮度/对比度、S 通道调饱和度、H 通道调色调，H 范围 0~180）
- 几何增强用 `cv2.getRotationMatrix2D` + `warpAffine`（边界用 `BORDER_REFLECT`）
- 裁剪后统一 `resize` 回原尺寸（先裁再缩放）
- **中文路径处理**：用 `PIL.Image.open` + `cv2.cvtColor` 读、`Image.fromarray(...).save` 写，
  绕开 `cv2.imread`/`imwrite` 不支持中文路径的问题
- 相关产物：`demo/1`（120 张原始样本，6 类 × 20 张）→ `demo/2`（600 张增强样本，6 类 × 100 张）

> 增强脚本与 `demo/1` → `demo/2` 的 1:5 扩样正好对应（120 → 600），见
> [../data/01-数据集与模型资产清单.md](../data/01-数据集与模型资产清单.md)。

## 六、实现难点与解决方法（原文表 1）

| # | 实现难点 | 具体表现 | 解决方法 |
|:---:|:---|:---|:---|
| 1 | 饮料分类受角度和光照影响 | 同一饮料在不同角度下外观差异较大 | 通过旋转、亮度、对比度增强扩充样本，提高模型泛化能力 |
| 2 | 木棍数量多且目标相似 | 容易出现漏检或重复匹配 | 调整最小匹配分数、角度范围、尺度范围和最大匹配个数 |
| 3 | 纸杯边缘提取不稳定 | 二值化后存在噪点或圆边缘断裂 | 使用 Sauvola 二值化和形态学开运算增强杯口轮廓 |
| 4 | 单杯与叠杯差异较小 | 半径变化细微，容易误判 | 通过圆查找提取半径，并根据多组样本设置判断阈值 |
| 5 | OCR 字符小且背景干扰强 | 点阵字符断裂、罐底反光明显 | 使用二值化、滤波、形态学处理，并采用带角度字符定位 |
| 6 | 缺陷形态不规则 | 污损、破损、变形差异较大 | 采用深度学习图像分割模型进行缺陷区域定位 |
| 7 | 结果展示不统一 | 不同任务输出形式不同 | 使用图形收集、耗时统计和输出图像模块统一显示与保存 |
